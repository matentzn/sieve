    SIEVE - a SEPIO profile for evidence-based curation of Mondo claims¶

    SIEVE is a profile of the SEPIO core information model (schema/sepio_core.yaml, imported unchanged). Every class here specialises a SEPIO core class. Every inherited slot keeps or narrows its core range. Nothing in the core is redefined.

    The profile is driven by the Mondo requirements collection (requirements/mondo_requirements.tsv). Each class, slot, enum and permissible value that realises a requirement carries it in annotations.requirements (space-separated requirement IDs) and, where a modelling decision lies behind it, in annotations.decisions (Mondo decision-log IDs). requirements/traceability.yaml assigns every requirement to a SEPIO design module and a disposition. tests/test_traceability.py keeps both sides consistent.

    Shape of the data: one EvidencePacket per claim. It holds one claim-type Statement (view B of D-041: identified, reified statement objects), the evidence items its lines refer to, and a version. Rules, policies, agents and information resources are shared reference data held in a SieveRegistry.

    Profile conventions: names follow the core's camelCase. Narrowed core slots are declared via slot_usage. Value sets for Coding-typed core slots are declared as bindings and enforced by sieve.profile_checks, because linkml-validate does not enforce bindings.
