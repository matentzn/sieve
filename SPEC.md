# sieve — System Specification

Status: as-built, reflecting the `main` branch after the migration onto the
SEPIO/SIEVE evidence model. This document mirrors what the code does today. Where
a capability is partial or a gap exists, it is called out in
[Known limitations](#known-limitations).

## 1. Purpose

**sieve** (Scientific Evidence Evaluation & Verification Environment) is a
curation application for reviewing ontology assertions against their supporting
evidence. A curator sees an assertion (e.g. "asthma `subClassOf` respiratory
system disorder") with the evidence supporting or disputing it, rates individual
evidence items, and accepts / rejects / flags the packet. Accepted packets are
exported as RDF `owl:Axiom` annotations for ontology workflows.

sieve is the human-review-and-export end of a two-tool system with its sibling
[`../mondo-ai`](../mondo-ai) (the extraction/scoring pipeline). **sieve now owns
the canonical SIEVE/SEPIO model** (`id: https://w3id.org/sieve`); mondo-ai is
expected to import it rather than keep its own copy.

## 2. Technology stack

- **Python** ≥ 3.10; **Pydantic v2** models **generated** from LinkML via `gen-pydantic`
- **uv** for dependencies, **just** as the command runner
- **LinkML** (`linkml`, `linkml-runtime`) for the schema, generation, and validation
- **DuckDB** for local storage
- **Streamlit** for the review UI; **Typer** for the CLI
- **rdflib** + **curies** for RDF generation and CURIE→URI expansion
- **Authlib** + **httpx** for ORCID OAuth
- **pytest** / **mypy** / **ruff** (all green in `just test`, gated by CI)

## 3. Package layout

```

  app.py               Streamlit review UI
  auth.py              ORCID OAuth + curator authorization
```

## 4. Data model (SEPIO/SIEVE)

The LinkML schema is the source of truth; `just gen-pydantic` regenerates
`datamodel/sieve_models.py`. `sieve.yaml` extends the trimmed SEPIO base in
`sepio_classes.yaml`.

```
EvidencePacket                     (tree_root; not a SEPIO Entity → no id/type tax)
├── id
├── statement: SieveStatement      is_a SEPIO Statement
│   ├── subject / subject_label
│   ├── predicate: Coding          (code + label + system)
│   ├── object / object_label
│   └── statement_text
├── has_evidence_lines: [SieveEvidenceLine]      is_a SEPIO EvidenceLine
│   ├── direction_of_evidence_provided  supports | disputes | neutral
│   ├── strength_of_evidence_provided   strong | moderate | weak
│   ├── score_of_evidence_provided      float
│   └── has_evidence_items: [ … ]      polymorphic InformationEntity subclasses:
│         ConcordanceItem | SieveDocument | SieveDataItem |
│         SieveStudyResult | ComputationalResult | AgentContribution
├── evidence_synthesis: EvidenceSynthesis   (summary, Score, direction, cited_evidence)
├── curated_by: CurationActivity            (is_a SEPIO Contribution)
├── status: CurationStatus                  UNREVIEWED | ACCEPTED | REJECTED | CONTROVERSIAL
└── created / updated
```

**SEPIO tax.** Every SEPIO `Entity` (statement, lines, items, activities, agents)
requires `id` + `type`. Standalone classes (`EvidencePacket`, `Score`,
`EvidenceSynthesis`, `Coding`) do not.

**Grafted sieve-specific features** (kept from the legacy model):

- **`CuratedEvidence` mixin** — `rating` (`CurationStatus`) + `eco_code`/`eco_label`,
  mixed into all six evidence-item classes. Per-item steward verdict + explicit ECO.
- **`CurationDecision`** + `DecisionType` — a decision *history* (curator, rationale,
  certainty, timestamp), stored in its own table.
- **GitHub/tool provenance** — `pull_request`, `issue`, `created_with` on
  `CurationActivity`; `mapping_set` (SSSOM) on `ConcordanceItem`.

`AgentContribution` carries the orthogonal scoring dimensions from SEPIO/SIEVE:
`trust_level` (community/domain_expert/curator/authority) × `channel` ×
`contribution_type`.

## 5. Ingest

`packet_ingest.py`: `ingest_packet_directory(dir, store)` loads each YAML packet
via `loaders.load_packet` (polymorphic dispatch by each item's `type`) and stores
it. `validate_packet_dict(data)` validates a packet against `schema/sieve.yaml`
(target class `EvidencePacket`) — imports are resolved via `SchemaView.merge_imports()`.
Evidence must be authored as explicit `EvidenceLine`s (no auto-wrapping).

## 6. Review UI

`app.py` (Streamlit): a dashboard (packet counts), a review queue (filter by
status, open a packet), a packet detail view (statement + evidence lines → items
rendered by type + NER), per-item Accept/Reject rating, and decision recording
(Accept/Reject/Controversial → `record_decision` + `update_status`). ORCID auth
(`auth.py`) gates rating and decisions.

## 7. Scoring

`scoring.net_evidence_ratio(packet)` = `(S⁺ − S⁻) / (S⁺ + S⁻ + S⁰)` over
`has_evidence_lines[]`, grouping each line's weight by `direction_of_evidence_provided`.
A line's weight is its `score_of_evidence_provided`, else a qualitative
`strength_of_evidence_provided` map (strong 1.0 / moderate 0.6 / weak 0.3), else 1.0.

## 8. Export

`packet_export.py`:

- **RDF** — `packet_to_rdf` / `export_packets_to_rdf` emit, per ACCEPTED/REJECTED/
  CONTROVERSIAL packet, an `owl:Axiom` over the statement's subject/predicate/object,
  a `SEPIO:0000124` reference to the packet, and status-specific annotations. For
  ACCEPTED packets it adds `oboInOwl:source` for the steward and for the sources of
  every `rating == ACCEPTED` item on a supporting line.
- **YAML** — `packet_to_yaml` / `export_packets_to_yaml`.

Both serialize with `serialize_as_any=True` so polymorphic evidence items keep
their subclass fields (otherwise Pydantic collapses them to the declared base).

## 9. Authentication

`auth.py` implements ORCID OAuth 2.0 (sandbox + production), authorizes curators
from `curators.yaml` with role-based access, and provides a dev-mode bypass.

## 10. Storage

`store.py` — `PacketStore` on DuckDB:

- **`evidence_packets`** — `id` (PK), promoted filter columns (`subject_id`,
  `predicate`, `object_id`, `status`, `evidence_score`, `evidence_steward`,
  `created`, `updated`), and `packet_json` (the full `EvidencePacket`,
  `serialize_as_any`). NER is computed on insert.
- **`packet_decisions`** — the decision history (`get_decisions`).
- Review helpers: `update_status`, `set_item_rating`, `list_packets`, `get_stats`.

## 11. CLI

`sieve <command>`: `run` (launch Streamlit), `ingest -I dir --db path`,
`export -i/-I … -O rdf|yaml -o out`, `validate -i/-I …`.

## 12. Testing and tooling

`just test` runs `pytest`, `mypy`, and `ruff` — all green; CI (`main.yaml`) runs
it on Python 3.10–3.13. `just gen-pydantic` regenerates the datamodel from
`schema/sieve.yaml`. The generated `sieve_models.py` is excluded from mypy and ruff.

## 13. Known limitations

- **Docs pages.** `docs/architecture.md`, `docs/data-model.md`, `docs/api.md`,
  `docs/cli.md` still describe the legacy flat model and need updating to the
  EvidencePacket shape.
- **mondo-ai hand-off.** mondo-ai still keeps local copies of the SEPIO/SIEVE
  schema; it should import from sieve (or a published `w3id.org/sieve`).
